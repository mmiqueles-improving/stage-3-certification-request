## Day 1 Verification (Actual Run)
- [x] Verified Ollama model: only `llama3.2:latest` is pulled locally (not `llama3.1` as originally configured). Updated `promptfooconfig.yaml` provider to `ollama:chat:llama3.2`.
- [x] Found and fixed: prompts used `${flowDescription}` (JS template-literal syntax) instead of promptfoo's Nunjucks `{{flowDescription}}` — variable was never actually substituted into the prompt.
- [x] Found and fixed: `promptfooconfig.yaml` used `assertions:` instead of the required `assert:` key — every test silently ran with zero assertions ("No assertions", trivial pass). This is why the original "40%/90%" numbers in the README were never actually measured.
- [x] Found and fixed: no grading provider configured for `llm-rubric` — defaults to OpenAI (`OPENAI_API_KEY` not available in this setup). Added `defaultTest.options.provider` pointing at local `ollama:chat:llama3.2`.
- [x] Found and fixed: `llm-rubric` prompts asked for a raw 0-5 score ("return only the score"), incompatible with promptfoo's pass/fail JSON grading contract. Rewrote as clear pass/fail criteria.
- [x] Found and fixed: structure regex (`Issue|Severity|Fix`) too loose — v1's free prose incidentally contains those words. Replaced with 3 required regexes matching the literal `**Issue**`/`**Severity**`/`**Fix Suggestion**` markdown markers from the v2 template.
- [x] Found and fixed: `not-contains: "improve the experience"` too narrow. Replaced with several `not-icontains` checks for unambiguous filler phrases (single words like "user-friendly" excluded — they caused false negatives inside otherwise-concrete suggestions).
- [x] Found and fixed: local grading model (llama3.2, 2GB) proved unreliable at *counting* heuristic mentions via `llm-rubric` (undercounted a critique that explicitly labeled 3 heuristics as having only 1). Replaced with a deterministic `javascript` assertion doing keyword matching against the fixed 5-heuristic vocabulary.
- [x] Found and fixed: `testcases/fixtures.yaml` wasn't wired into `promptfooconfig.yaml` at all (tests were duplicated inline) and used the wrong external-test-file format (missing `vars:` wrapper). Fixed format and wired via `tests: file://testcases/fixtures.yaml`.
- [x] Ran `npm run eval` end-to-end with real grading: **v1 = 0/5 (0%) pass, v2 = 5/5 (100%) pass.** This is a legitimate, reproducible result (not the old placeholder numbers) — see `results/day1-final2.json`.
- [x] Judgment: reviewed actual critique text in `promptfoo view` for both versions. v1 (no structure/persona) is discursive and leans on generic framing ("...to improve the user experience") mixed in with some genuinely OK suggestions. v2 (structured, persona, explicit constraints) consistently cites specific UI states, labels a heuristic per issue, and stays concise. The rubric's judgment matches my own read as a designer.

## Day 2 — Introduce v2, Compare
- [x] `npm run eval` (v1+v2 combined) was already run on Day 1; reviewed the results side-by-side today in `promptfoo view`.
- [x] Observation: the difference between v1 and v2 output is notorious/obvious — driven almost entirely by the structure and detail each prompt template asks for, not just model variance.
- [x] Both v1 and v2 critiques contained suggestions, but only v2's prompt explicitly requires a labeled field for it: `**Fix Suggestion**: [concrete, implementable fix]`. v1 never asks for this, so its suggestions are buried in free-form prose.
- [x] Judgment: v2 is meaningfully better at turning critique into actionable items, because its prompt also requires "Issue," "Severity," and a named "heuristic" per item as a structured list — for design critique, a structured checklist beats one big paragraph.
- [x] Result: all 5 v1 cases failed, all 5 v2 cases passed. This is driven by (a) v1 having no structure/persona at all, and (b) the rubric being simple — see limitation below.
- [ ] **Rubric limitation identified**: of the 4 assertions in `defaultTest.assert`, only 1 (actionability) is actually LLM-graded (`llm-rubric`), and it's binary pass/fail — not a graded scale. This means the rubric can tell us both prompts passed/failed a low bar, but can't distinguish "v2 is clearly better" from "v2 is only marginally better" than v1. Next step: either move to a graded 1–5 `llm-rubric` scale (promptfoo supports a `threshold` on rubric scores) or add more finer-grained rubric assertions.
